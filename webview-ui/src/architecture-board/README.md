# Architecture board presentation

The standalone board renders immutable semantic diagrams. Layout, selection, colors, routing, and review UI belong here—not in the task loop, tool module, or semantic schema.

## Reading a board

- Every successful save automatically opens the exact committed version through extension code; the model does not need a separate display call. Explicit display operations open existing diagrams or exact-version before/after comparisons. Successful presentation retains **Open diagram / Open comparison** navigation on the transcript card for reopening. Distinct diagram names have separate panels; another version or comparison reuses its named panel.
- Interactive mode waits for feedback through either a direct chat reply or explicitly submitted board comments, equally valid channels. Autonomous/YOLO mode also opens the board and returns `displayed` without waiting. Opening or closing a board is not a reply or approval, and successful opening is not visual verification of rendering.
- Validation/save errors return to the model for correction without opening a board. A display failure after publication retains `saved: true` and the committed `name`/`version`: recover by displaying that exact version, not by saving a duplicate. Display failure does not start a feedback wait. Hosts without a viewer do not expose the diagram tool.
- A single board uses two fixed-height 36px rows: identity/version and review actions above, presentation controls below. Style is aligned with search and Labels; zoom sits beside Fit. Fullscreen is a quiet utility and Send Feedback shows a count only when positive. Narrow controls keep accessible names without wrapping into another row.
- Version options live beside the title. A labeled update action appears only for a known newer version; unknown availability is not treated as up to date. Single views can Follow latest from the version menu. Comparison panes retain fixed snapshots: changing one pane's version preserves the other. **Reload board** is in **Board options**; errors retain local Retry actions.
- **Diagram & comments** opens the summary, small node/relationship counts, and general comment thread in one sidebar. Element previews open that same sidebar through **Details & comments**. Legends and interaction guidance live under collapsed **Reading the diagram**, not a separate About popover. The textual alternative remains collapsible.
- **Open diagram / Open comparison** reveals a normal editor panel without changing window mode or settings. Only the explicit **Go Fullscreen** control requests native VS Code Zen Mode. The header changes to **Press Esc to return** after host confirmation; clicking that control also exits. Escape dismisses overlays first, then exits Zen Mode. The same webview and comment drafts survive transitions. Requests are serialized and shared across board panels.
- Zen Mode respects the user's existing `zenMode` preferences; the board never writes them. Whether entry uses OS fullscreen or centered layout depends on those preferences. This is workbench-wide native Zen Mode, not a separate window. Escape is caught at the webview's **document** after local overlays; the native **Escape Escape** chord while the board is active also uses the shared exit command. VS Code has no public Zen Mode state/event API: unrelated native menu/shortcut toggles and Zen Mode already active before the extension starts remain outside this tracking. Actual desktop transitions require manual integration verification.
- **Fit** changes only the viewport to show the whole diagram, even when that makes text small. Initial placement and **Redraw**, under Fit's **Layout options**, use a reading-scale floor of 14 screen pixels for 18px leaf titles. Large diagrams therefore require panning; Fit remains the explicit overview. Redraw replaces manual positioning, not semantic content. Resizing and style changes do not rearrange cards. Existing saved positions and zoom are preserved on reopening; use Redraw if older positions need more room for measured labels.
- Drag empty canvas or an empty subsystem interior to pan. Drag a card to move it, or a subsystem's header to move its frame and children. Previews open on completed clicks or Enter/Space activation, never on pointer-down or drag selection.
- Select a component or relationship to highlight its neighborhood and open a small, screen-space preview without moving the canvas. **Details & comments** opens the inspector. **Escape** closes the inspector back to the preview, then closes the preview on the next press, including when a comment field has focus. Drafts are retained. Search, toolbar menus, and the textual alternative also dismiss with Escape.
- Both component and relationship previews include an inline comment input. **Save comment** stores a pending comment on that exact element/version; **Details & comments** shows its full thread. The inline composer and inspector share drafts, errors, and retry behavior. Switching targets or closing a preview does not discard text.
- Relationships start with fine, muted strokes and restrained markers across all styles. Hovering or highlighting a neighborhood adds emphasis; clicking a relationship makes its line and marker stronger. High contrast keeps idle connections fully opaque. Hover reveals its label; **Labels** shows all labels without thickening every connection. Arrowheads, ownership diamonds, line weights/patterns, generous invisible hit areas, and labels keep readable screen sizes as you zoom out.
- Search or double-click a component/subsystem to focus it. **Details & comments** contains responsibilities, rationale, connected relationships, code references, and comments. In narrow panes it appears below the canvas instead of covering it.
- Comments stay local until **Send Feedback**. Direct chat is an equally valid way to give feedback, but does not collect or submit pending board comments. Hiding details preserves drafts; closing the board panel does not persist uncommitted drafts.

### Color is information

Relationship colors keep the same meaning across diagrams and versions:

| Relationship | Color | Additional cue |
| --- | --- | --- |
| API call / control flow | Blue | Solid directed line |
| Data flow / returned results | Teal | Dotted directed line |
| Dependency | Amber | Dashed directed line |
| Ownership / aggregation | Violet | Hollow diamond at the owner |
| State transition | Rose / raspberry | Solid line, open V arrowhead |
| Participant message | Graphite (light) / silver (dark) | Dash-dot line, filled arrowhead |

The relationship legend is visible on the canvas. **Silhouette carries node type; text carries meaning.** Every theme uses the same approved shapes: connector-tab components, stepped-shoulder compartmented classes, capsule functions, cylinder databases, chamfered services, single-opening API sockets, short-rounded state rectangles, and circular actor medallions. Earth and Linen supplement these shapes with kind labels and glyphs; Soft also labels states and actors explicitly. Subsystems are frames with style-owned fills and headers. These are board conventions, not strict UML. `nodeShapes.ts` delegates outlines and docking to the shared pure geometry; the canvas and About/inspector legends share its visual vocabulary. Native tooltips, accessible names and element details retain explicit kinds.

The retained themes are **Linen**, **Earth**, and **Soft**. Palettes, decorations, and kind descriptors remain style-owned; primary label typography and safe text regions are shared. Titles retain priority; long identifiers prefer word, separator, and camel-case breaks over arbitrary splits. Inspect `fixtures/visual-vocabulary.json` for all nine node kinds and six relationship kinds together.

Selection strengthens the actual silhouette outline and connected relationships while unrelated elements fade. Proposed additions/modifications/removals and pending/submitted comments remain explicitly labeled, separate from type meaning. Ordinary VS Code theme colors do not enter board palettes. High-contrast themes explicitly override them with foreground-colored silhouettes and connections, retaining structural details and line patterns. Reduced-motion preference disables focus/zoom animation and opacity transitions.

## Concrete node types

Node kinds are authored semantic facts. The authoring skill requires source inspection and exact code references before publishing implementation-backed nodes: classes use `class`, functions/methods use `function`, and runtime services, persistent stores and API boundaries use their own kinds. `component` is reserved for genuine composite/logical units or explicitly unresolved entities, not a default for every code symbol. A storage class and its stored data are different entities.

The canvas, preview, inspector and legend render that saved kind consistently; they must not infer a different type from a label, filename or incidental related-code reference. An incorrectly generic existing node needs a source-verified new semantic version, preserving stable IDs and relationships. Style changes and Redraw do not reclassify immutable content.

### Interaction vocabulary

`state` represents a persistent condition such as “Feedback pending,” not an operation or a live execution indicator. States use 224×112 short-rounded rectangles with turquoise/petrol surfaces; they are not the pill-shaped function silhouette. `actor` represents a human or software participant with agency, not a container or an automatically generated swimlane. Actors use 168×168 rose/raspberry circles; their labels stay inside an approximately 116×116 safe inner square. Short names work best. State and actor kind labels remain explicit in every theme.

`transition` connects states and describes a change of condition. Use an `event [guard]` label, with longer effects or conditions in the description. `message` describes communication between participants without asserting a synchronous call, receipt, or consumption. Keep actor communication separate from concurrent conversation, board, and feedback state machines; a message need not imply a transition. These are descriptive diagrams, not executable statecharts.

Node and relationship colors are independent vocabularies: a rose transition is not actor-owned. Transitions retain rose/raspberry identity with an open arrowhead; messages use neutral graphite/silver with a dash-dot line, distinct from existing dotted data flow and dashed dependency. Soft uses more saturated turquoise and raspberry fills/outlines to separate states from mint databases and actors from peach service cards. High contrast intentionally replaces color with accessible foregrounds while preserving silhouette, line pattern and arrowhead meaning. Selection is emphasis, never an “active state” marker.

## Plug-and-play visual styles

The header's **Style** dropdown applies to both comparison panes and to existing diagrams without regeneration. **Earth** is the dark-mode default: warm whole-body gradients on a near-black canvas. **Linen** is the complementary light-mode default: warm ivory/chalk surfaces, charcoal text, subtle sage subsystem boundaries, and restrained light fills with darker outlines. Both preserve kind identity: sage/olive classes, slate composite components, plum services, ochre functions, terracotta databases, and blue API endpoints. **Soft** retains its pastel palette. All three use the same silhouettes, measured dimensions, and primary font. Explicit selections keep their own palette regardless of ordinary editor appearance; high contrast overrides decorative colors and effects.

Styles compose visible node content and group headers inside a shared interaction shell. Theme-independent text metrics keep positions, dimensions, frames, routes and viewport stable on palette switches. Class titles occupy the body below the compartment divider; API text clears the socket recess. No subtitles are invented from descriptions: the semantic schema currently has no short-caption field. Switching between retained themes does not reroute or rearrange. Routing failures remain visible and Redraw is explicit.

VS Code stores the last explicit selection in the user-level `dirac.architectureBoard.style` setting. Reset that setting to its default `auto` to follow appearance again: Earth for dark mode and Linen for light mode. Removed or unknown style IDs also fall back to the appearance default. VS Code theme changes update the default live without replacing an explicit retained selection; standalone browsers use their color-scheme preference. The host broadcasts configuration changes to open boards; no diagram versions, presentation sidecars, task state or model prompts store this preference. Preference-write errors appear with a retry action. High-contrast themes remain authoritative over every palette.

Each optional style is self-contained under `styles/<id>/`:

- `style.ts`: default `BoardStyle` export with a directory-matching ID, label, order, pure geometry and relationship stroke settings. It must not import React, CSS or browser APIs: the worker loads it too.
- `style.css`: scoped rules using `.architecture-board[data-board-style="<id>"]`, including native canvas, card, group, text, outline and grid tokens. Do not read ordinary VS Code theme classes or color variables. `styles.css` maps tokens and supplies the high-contrast override; `board.css` owns shared structure and interactions. `typography.css` is authoritative for measured primary labels and descriptor positioning; themes must not override their metrics or safe regions.
- Optional `Presentation.tsx`: named `NodeContent`, `GroupHeader`, and/or `LegendGlyph` components. Content receives kind, label, dimensions and a reusable safe title. It owns composition, not handles, selection or comments. Missing components use the original title/silhouette. `SemanticNodeContent.tsx` supplies reusable class/header composition without fake text.
- Optional `NodeAppearance.tsx`: default noninteractive decoration component for secondary ink or construction marks. Decorative contours must not transform the primary silhouette or change measurements.

Vite discovers these files using `import.meta.glob`; the catalog contains only Linen, Earth and Soft. Earth and Linen are the built-in dark/light fallbacks. Every theme imports `boardGeometry` from `styles/boardGeometry.ts`, which also owns the shared per-kind leaf dimensions. Shape math lives in the shared geometry modules; filleted polygons use the same quadratic segments for drawing and orthogonal projection. Rendering, handles, candidate search, docking and validation use this geometry, including curved group endpoints approached from inside or outside the frame. Optional `nodeGradient` uses theme-owned `--node-surface-top` / `--node-surface-bottom` stops; high contrast flattens the fill. UI/CSS discovery remains separate from the worker-safe catalog. The shell alone owns selection, accessible names, handles, proposal indicators and real comment badges.

## Layout and persistence

`flowGraph.ts` builds parent-first React Flow nodes and distinct handles for every relationship. `layoutGraph.ts` requests deterministic ELK Layered placement and converts group-relative routes to canvas coordinates. `routeLayout.ts` runs fixed-port cleanup, endpoint optimization and silhouette docking in order. `routeCleanup.ts` establishes safe routes; `routePorts.ts` improves attachments; `orthogonalRouter.ts` searches for short orthogonal paths; `lineJumps.ts` plans crossings; `edgeGeometry.ts` renders rounded bends and curved hops.

### Measured text fitting

Primary titles use bundled Inter Medium, 18px/25px with normal tracking; group headers use 16px/24px and relationship text 13px. Kind descriptors retain their existing font treatment. The local Latin and Latin Extended WOFF2 subsets are licensed under OFL (see `fonts/`); other scripts use the platform's system fallback. Both subsets finish loading before sizing begins. Font-load failures are visible, and no runtime network font service is used.

`textLayout.ts` supplies pure wrapping and conservative per-shape title/descriptor regions. `measureText.ts` measures complete candidate strings with actual browser font metrics, including fallback glyphs, and keeps a bounded 4,096-entry width cache. Sizing evaluates at most three uniform shape tiers (1×, 1.2×, 1.4×), choosing the first complete fit; otherwise it chooses the tier exposing the most text. Node text never shrinks to fit. Class compartments, cylinder caps, socket recesses, capsule ends, the actor's inscribed square, and proposal space are excluded from the title budget. Group comment badges reserve header space without relayout.

`NodeTitle` renders the measured lines, rather than letting a second CSS wrapping algorithm disagree. Wrapping prefers Unicode word and identifier boundaries, falls back to grapheme-safe breaks, respects explicit newlines, and measures the ellipsis inside the final line. Labels are capped at four lines (one for group headers), with full originals retained in accessible names, previews, and details. Relationship labels use browser-measured three-line clamping at constant screen size; this bounds individual labels but does not solve collisions between all visible edge labels on dense graphs.

Sizing is independent of zoom and palette; zooming does not reflow text or rearrange nodes. Initial placement/Redraw/focus preserve a readable leaf-title scale, whereas explicit Fit permits a complete smaller overview. Arbitrarily large graphs cannot guarantee both at once. Unit cases are in `textLayout.test.ts`; `fixtures/text-readability.json` supplies long names, paths, multilingual text, emoji, and proposal badges for production-browser inspection.

Initial placement and explicit Redraw sample the actual pane, including each comparison pane independently. `layoutSpace.ts` allocates bounded gaps from usable area and measured card footprint, applies spacing inside groups as well as at the root, and partitions subsystem aspect targets by descendant-card count. It never stretches cards or reacts automatically to resizing. Headless callers without a canvas retain the original 16:9 policy.

`layoutCandidates.ts` compares unwrapped, root-wrapped, subsystem-wrapped, and both-wrapped placements, each with and without ELK `EDGE_LENGTH` post-compaction. Canvas-aware boards with multiple wrappable top-level groups also consider partitioned subsystem targets (at most ten candidates; eight without partitioning; four without wrappable groups; one without relationships). Group endpoints are not wrapped internally because ELK's MULTI_EDGE algorithm cannot handle compound-node ports; their parent/root can still wrap. Placement, route conversion, cleanup, and selection all run in one killable worker under a shared 10-second deadline. The worker adapts ELK's synchronous native register/layout dispatcher, not its incompatible in-process Worker shim.

`routeGeometry.ts` supplies absolute bounds and orthogonal intersection checks. The initial cleanup preserves ELK ports, avoids conservative node envelopes with 8px clearance, protects group title bands and unrelated group interiors, and permits legitimate ancestor traversal. A coordinate-compressed A* search favors wire length, then bends. Other edges do **not** block perpendicular crossings; parallel runs use separate lanes (4px minimum). Search is deterministic under one caller-owned allowance: the cleanup's 4,000,000 checks count segment collision tests and frontier visits, including stale entries. There is no independent per-search visit cutoff that prematurely exhausts that shared allowance. Uncompleted searches retain existing ELK paths and report their IDs in diagnostics; strict fixed-position recovery reports failure instead of retaining an unchecked seed. This is bounded, sequential routing, not a global optimum over all placements and routes.
Short local connections are routed before long ones, and straight connections shorter than two port stubs stay straight. Search reserves 8px of straight space around crossings and prevents new bends within that distance of an existing line, instead of discovering unbridgeable corners after routing. The coordinate grid includes these hop-clearance boundaries. The pathfinder's admissible distance estimate includes unavoidable single-obstacle detours, using their maximum rather than their sum so shared detours are not double counted. Cached distance/turn-clearance estimates and a remaining-bend heuristic keep search focused even when distant relationships add many grid coordinates. Normalization aligns sub-EPSILON coordinate noise before dropping tiny bends, preserving orthogonality.

Once cleanup is valid, endpoint optimization considers all four sides of leaf nodes, including right-side targets. It evaluates complete obstacle-safe paths including their silhouette insets, not center distances, and commits only shorter visible routes (or equal-length routes with fewer bends) that preserve hop space and separate terminal lanes. New slots stay at least 12px from other ports on the same side; existing ELK ports remain available. A 24px approach can hop across a nearby outgoing lane; narrow corridors retain 12px approaches. Optimization has an independent 600,000-check budget, 40,000 per relationship and 4,000 per probe, so a difficult early edge cannot consume all the work. Budget exhaustion leaves the checked route intact. Self-loops and explicit group endpoints retain their existing port constraints. Diagnostics expose `portChecks` and `reattached` IDs. `nodeShapes.test.ts` and `routePorts.test.ts` cover the shared geometry and right-side target regression.
Port-candidate ordering and budget allocation belong to `routePorts.ts`, not the pathfinder. It visits distinct source/target side pairs before retrying alternate slots or stub lengths for the same sides. Within each round, candidates are ranked and pruned using the pathfinder's geometric distance bound plus terminal/docking distance. Candidate failure never relaxes clearance or hop validation.

Final endpoints project orthogonally onto the actual silhouette: arrows meet capsule curves, cylinder lids, module tabs and API sockets rather than invisible rectangles. Only the checked outward terminal segment may traverse its own shape inset; other node envelopes remain obstacles. React Flow handles use the same projection. Route recovery reverses projection before searching, and neither endpoint choice nor docking changes node positions, group sizes, semantic edges, or saved viewport. This same pipeline is used for Redraw and fixed-position drag/reopen recovery.

`lineJumps.ts` assigns one stable owner to each crossing, independent of hover, selection, or drawing order. Close crossings on the same segment share an elongated hop. The over-line uses a real semicircular/elliptical SVG arc; the under-line has a small transparent path gap where the arc passes, never a background-colored mask. Arcs avoid protected bodies and neighboring parallel runs. Contacts without room near corners/ports trigger up to four local repair passes; candidates with unresolved contacts are rejected. Intersection work has its own 2,000,000-check cap under the worker deadline. Shared terminals are not hops. Radii target 6 screen pixels but are constrained by checked geometric space (at most 16 canvas pixels); dense or far-zoomed-out diagrams cannot maintain a constant apparent hop size. Colors and dashed/dotted strokes remain unchanged, arrows stay on terminal paths, and continuous transparent interaction paths keep the entire relationship selectable. Labels prefer straight intervals away from hops.

A failed routing shortcut must not discard an otherwise screen-shaped placement. If hop-aware routing and local repair cannot finish, `routeCleanup.ts` restores only the relationships involved in the contacts or overlapping restored lanes, then recomputes hops. There is no whole-graph reset. Each changing pass restores at least one previously changed route; 500,000 lane checks bound recovery, with an explicit error on exhaustion. Contacts still invalid in the recovered geometry reject the candidate. Diagnostics distinguish unfinished searches (`retained`) from rolled-back shortcuts (`restored`). Route conversion rounds coordinate noise to one millionth of a canvas pixel so floating-point differences between ELK containers cannot falsely invalidate orthogonal segments.

`layoutQuality.ts` rejects overlapping placements before routing; repairable ELK paths may proceed through cleanup. Final validation still rejects overlaps, detached ports, missing/diagonal routes, protected-body intersections and unresolved hops. `layoutSpace.ts` measures fitted screen-space scale, nearest-card crowding, unused canvas and normalized wire length. `layoutCandidates.ts` prioritizes that composition cost so short wiring alone cannot eliminate a roomier, more legible placement. Readability and crowding outweigh filling empty area; dense graphs still require zoom or focus. Headless callers retain the original Pareto-filtered `extent² × total wire length` policy, using 16:9 extent. Geometry, wire length, bends and stable IDs break ties. Optional compaction changes placement; cleanup does not move nodes.

This is not a CSS aspect-ratio box, image stretching, cropping, or padding to manufacture a ratio. Topology, meaningful groups, and readable card dimensions take priority over an exact rectangle. No model-generated coordinates or new semantic fields are needed. The authoring skill asks for focused graphs, concise labels, and truthful grouping, not geometry tricks. Existing layouts stay unchanged until Redraw is chosen.

Group frames start from a shared canonical minimum size; their expanded bounds are layout outputs, never seeds for another layout. This keeps fresh layout, repeated Redraw, and route recovery deterministic instead of allowing saved group sizes to alter wrapping. Minimum leaf dimensions are shared across themes: class 224×160, database 198×164, function 280×100, API 216×196, component 248×128, service 224×160, state 224×112, and actor 168×168. Text sizing may expand these by up to 1.4×. Older saved positions are retained rather than silently rearranged; use Redraw if the new dimensions need more space.

Routes, port stubs, and hop metadata are transient view data, not semantic content or new sidecar fields. Reopening recovers arranged ports when computed positions match the saved positions; otherwise a route-only worker request uses the saved geometry. Moving a node invalidates routes and hops together. Drag release and keyboard movement trigger route-only recovery without changing positions or viewport. If fixed geometry cannot be routed safely, the board surfaces an error and retains live-endpoint fallback paths; the user can move cards apart or explicitly Redraw. Cancellation and worker failure still expose the textual alternative.
On a saved-position mismatch, recovery restores canonical group dimensions only when every descendant's relative position and measured leaf size still matches that arrangement. Moving an external node or translating a whole subsystem therefore does not shrink unchanged frames on reopening. A differently arranged subtree keeps bounds derived from its saved children, never importing wider frames from another placement. `groupRecovery.test.ts` covers this distinction.

Presentation save and review/draft notices float outside document flow so saving or typing an inline comment cannot resize the canvas. Only user viewport gestures trigger `onMoveEnd` saves; explicit fit/focus/zoom actions save themselves. Container resizing neither relayouts nor saves the graph, and preserves the viewport transform.

## Copy diagram image

Each pane has **Copy image**, which copies its complete current arrangement as a 2× PNG with an opaque theme background and 32 canvas-pixel margins. It uses the pane's **Labels** toggle, not temporary hover/selection labels. It preserves authored change badges, while excluding selection/dimming, comments, handles, toolbar, legend, and popovers. The image has the same existing label truncation and any label overlaps as the board; export is not a new layout pass. In comparison mode each button copies only its own pane.

`image-export/exportSnapshot.ts` takes an isolated value snapshot and checks bounds. `renderDiagramImage.tsx` owns a temporary offscreen React Flow instance at zoom 1, using the existing node/edge renderers and loaded theme. It measures rendered headers, labels, and paths before rasterizing, so pan/zoom and screen-sized markers do not change output. It never calls live viewport setters, layout workers, presentation saves, or host RPC. Temporary roots are removed on success/failure; disposal cancels pending export. `CopyDiagramImage.tsx` owns per-pane status and the explicit download fallback; `imageClipboard.ts` starts the promise-valued ClipboardItem write during the original user gesture.

The encoder is pinned to `html-to-image@1.11.11`: 1.11.13 deep-clones SVG descendants without their computed styles, losing our gradients and relationship colors. Upgrading requires inspecting actual PNG output, not just checking that a blob was returned. Bundled font CSS is supplied explicitly, avoiding stylesheet/font network requests under the existing `font-src data:` / `img-src data:` CSP. No remote image-generation service is used.

Exports are capped at 8192 physical pixels per side and 16 million pixels total. Larger diagrams fail explicitly rather than silently cropping or reducing resolution. Copy is unavailable while layout is running or failed; dragging/unrouted snapshots are rejected. Clipboard denial/unsupported browsers retain the generated PNG and show **Download PNG**; no success is reported until clipboard writing resolves. The download URL is revoked on dismissal, replacement, or unmount. Native VS Code clipboard/download permissions still depend on the host environment; a browser preview is not native-host verification.

Unit coverage for snapshot isolation, bounds, clipboard timing/failures, action status, fallback, and disposal lives in `image-export/*.test.*`. Production-browser inspection should include all styles, nested groups, cycles/self-loops, offscreen/negative positions, Labels on/off, comparison panes, and clipboard denial. Compare PNG pixels across zoom/selection changes and verify the live viewport and presentation remain unchanged.
